# G0 to G3: bounded experiments and decision rules

This plan is fixed BEFORE G1 is run. G0 is an exploratory implementation sanity test, not a preregistered language-quality study. The full G1/G2 runner, corpus and network adapters remain prerequisites.

## G0: reference correctness (current iteration)
Run pure-Python receipt and optimizer tests; compare Nesterov arithmetic against torch.optim.SGD; test causal masking, finite gradients, tied parameter count and content-disjoint fixture splits. Instantiate the exact 22,029,696-parameter model for three FP32 steps on a 128-token repeated random input. Separately compare single-model global-batch AdamW, local FedAvg H8, DiLoCo-style H8 and H32 on a 102,720-parameter decoder and 32,768 target tokens, seeds 11/23/37. All learners are sequential objects in ONE CPU process. No sockets, GPU, corpora, public clients, remote jobs or paid calls.

G0 checks implementation invariants, records learning curves and exposes optimizer differences. It does not establish WAN savings, natural-language convergence or useful model ability. Report every seed. Runtime is not distributed speed. Current scripts check the time budget before each local step, not at an OS-enforced hard deadline.

## G1: small English-language optimizer study (not executed)
Prerequisites: license/provenance record; exact raw-file verification; frozen TinyStories subset, tokenizer and split hashes; local data reader; AMP behavior and complete resume tests; immutable source/environment lock. The reference requires review before training a shared corpus. Never replace a missing data/hash prerequisite with random tokens and call G1 completed.

Model: Commons-Lab-22M. Four logical learners. Each local optimizer step processes 4096 nonpadding targets: context 512, microbatch 2 sequences, 4 accumulation steps. The single-model baseline accumulates 16 such microbatches for an effective 16,384-target global step. Compare the SAME predetermined sequence of target tokens per seed and preserve a ledger of actually used samples. No-failure candidate workers receive disjoint deterministic partitions of each global step.

Screening budget: 16,777,216 aggregate target tokens, 1024 local steps/learner. Confirmation budget: 100,663,296 targets, 6144 local steps/learner. At H8 confirmation has 768 outer exchanges; at H32 it has 192. These are partial-training optimization budgets, not compute-optimal model-training promises. Repeat seeds 11,23,37 for confirmation. The screening run chooses ONE candidate using the development set, with an identical screening allowance for the baseline. No test-set tuning.

Methods: S = one model with global-batch AdamW; F8 = local AdamW + FedAvg; D8 = local AdamW + Nesterov outer H8; D32 = the same with H32. Fixed initial values appear in study.json. Actual DDP is a separate multi-GPU/transport baseline, not the serialized S implementation. Different optimizer states mean H1 FedAvg/DiLoCo is NOT generally identical to multiworker global-batch AdamW.

Selection budget: at most one 16M screening run per listed method initially. If no candidate passes, record failure and propose a NEW versioned hypothesis; do not keep searching silently. Before confirmation freeze selected method, exact hyperparameters, training duration/tokens and seeds in a committed manifest. Do not compare different data volumes or choose the best checkpoint after looking at the final test.

Primary statistic: token-weighted held-out cross-entropy in nats/target token with the SAME tokenizer. Report per-seed baseline/candidate differences, mean, SD and worst difference. Initial engineering equivalence margins for CONFIRMATION: mean excess NLL <=0.03 and worst-seed excess <=0.06. These thresholds are our declared tolerance (exp(0.03) is about a 3% perplexity ratio), not a theorem or statistical confidence bound. With only three seeds, no high-confidence population claim. Also report bootstrap uncertainty over independent held-out stories where feasible, not token-iid confidence intervals.

Select the final checkpoint by a predeclared fixed token budget; learning curves use regular 524,288-token intervals. For time-to-quality, threshold is the baseline's development NLL at the same confirmation budget, crossed at two consecutive scheduled evaluations. Use final test only after method/checkpoint selection; report all runs and exact processed/accepted/lost token counts. A decreasing training loss alone is not a pass. Absolute perplexity across different tokenizers is not comparable.

Calibration before the screen: 20 warmup and 100 measured local GPU steps, sequence 512 and declared batch/AMP, synchronized timing, peak allocated/reserved VRAM, model+optimizer memory, host RAM, actual upload/download baseline. No throughput extrapolation from the 128-token CPU probe. Target allocated VRAM <=4.5 GiB on a 6 GiB card, leaving operating margin; this target is not yet verified. Repeat a smaller microbatch with fixed effective tokens before shrinking the model.

Duration: time = processed-target-token budget / MEASURED end-to-end targets per second. A hypothetical 5000 aggregate targets/s would make 100,663,296 targets take 5.59 hours; at 1000 targets/s it takes 27.96 hours. Neither is a measured estimate for the owner's RTX 5070. Count evaluation, failed work, checkpointing and transport separately and in total. Initial calibration cap: 15 minutes; initial owner-hardware experiment cap: 2 GPU-hours total, no paid external compute or >3 GB source download without a stated budget. Stop at the cap with INCOMPLETE, never PASS. No unattended full training run is launched in this iteration.

Abort immediately on non-finite loss/gradients, bad data hash, out-of-range tokens, incorrect checkpoint lineage or consent revocation. Stop after three consecutive validation checkpoints worsening by >0.1 nat from the best development value and log the failure; this is an experimental budget rule, not proof of divergence. Do not auto-change model/data/LR to hide failures.

## G2: physical WAN cohort (not executed)
Only after G1: 3-4 known physical hosts on >=2 independent networks; record exact hardware and geographic/network scope. Compare full-sync DDP over the same shaped/actual links, D8/D32 selected at G1, and single-device quality/time. Shape bandwidth at 20/100 Mbit/s and latency at 20/100/200 ms in a controlled environment; do not call shaped links measured home Internet. Complete a separate natural-network run.

Measure payload AND interface bytes, retry volume, learner idle time, verifier work, all-node energy/cost estimates, accepted/lost data, throughput, quality and p50/p95 cancellation. Include initial dataset/checkpoint distribution and resumption cost in total campaign accounting. H8 means eight times fewer exchanges, not automatically eight times fewer bytes. Ring-allreduce and star topology have different accounting: specify precision and directions. Compression remains OFF until its own quality test.

Initial advancement criteria: G1 quality margins still pass; >=4x fewer measured training-exchange bytes than the declared full-sync WAN baseline; >=1.25x better wall time to matched development quality than that WAN baseline; no claim of speedup versus a local datacenter unless directly measured. Record the single-GPU comparison even when it is unfavorable.

Stress schedule: 0/10/30% worker unavailability; one slow worker at 0.25x rate; restart after a local checkpoint; network partition; duplicate upload; stale base; corrupt data; interrupted checkpoint write. Stable run accepts all four; failure runs use a stated minimum quorum (initially 3 of 4), deadline/grace and actual token weighting. If there is no quorum, no canonical model advance. Lost worker compute counts as spent; re-issued examples are not counted as new unique data. Survivors do not magically recover a failed worker's Adam moments. Restart either restores the matching local snapshot or records a fresh optimizer reset under a predeclared policy.

Participant stop target: cooperative work halts within 5 seconds in the admitted workload; this is measured under kernels in use, not promised by a web button. If a worker cannot be confirmed stopped, show unknown/stopping, not stopped. The campaign can last weeks while jobs/checkpoints are bounded. Human device shutdown remains allowed.

## G3: federation and adversarial review (not executed)
Add at least three independently administered operators, replicated metadata/checkpoint manifests, independent mirrors, authority revocation and real failover. Test primary loss, stale leader, partition and conflicting checkpoints. Do not invent a new consensus scheme: choose/review a maintained implementation for the declared crash-fault model. A signature quorum alone is not Byzantine consensus. The anonymous-adversary model needs separate model-poisoning, identity/admission and verification analysis before broader participation.

## Stop/go summary
G0 passes only implementation checks. G1 earns an optimizer candidate. G2 earns a bounded useful distributed-training claim. G3 earns a specific federation/failure claim. None automatically earns ASI, global public release, no-trust security or millions of active devices. Next public announcement may describe this research program and invite independent reviewers; it cannot announce a completed backend.
